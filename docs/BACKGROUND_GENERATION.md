# QStash無料枠でのバックグラウンド生成（Sites版）

この文書は本人専用Sites版の設定です。D1・QStash連携の実装と検証スクリプトはSitesのソースリポジトリで管理し、このNext.jsリポジトリとは別です。

2026-09-27時点。Renderの有料サービスは使用しません。バックグラウンド生成は、QStashから本人専用Sitesへの疎通確認が成功するまで無効です。

## ユーザーの接続手順

1. https://console.upstash.com/ でQStashを開き、対象リージョンが **Free** プランであることを確認します。有料プランへの変更や決済情報の登録はこのアプリから行いません。
2. QStashのQuickstartで `QSTASH_TOKEN` と `QSTASH_URL` を確認します。
3. 本人専用Sitesの「AI設定」→「画面を閉じても生成を続ける」にトークンを貼り、URLと同じ接続先を選びます。
4. Freeプランの確認欄にチェックして「接続して有効にする」を押します。
5. 「利用可能」になったら、新しい生成または「続きから生成」を開始します。既にブラウザで実行中の生成は自動移行しません。

トークンをチャット、GitHub、スクリーンショットに載せないでください。入力欄はパスワード形式で、サーバー側でAES-256-GCM暗号化してD1に保存します。ブラウザの永続ストレージには保存しません。

## 構成と実行

- 生成開始時にジョブをD1へ保存し、最初の工程をQStashへ登録します。
- QStashが認証付きで `/api/generation/runner` を呼びます。スマホの通信とは独立したリクエストです。
- SitesでDeepSeekを呼び、工程の結果と次の工程を保存してから、次のQStashメッセージを登録します。
- QStashへ送る本文はジョブIDと工程IDだけです。DeepSeekキーとシナリオ本文は送りません。
- QStashにはSites接続用トークンと実行API用秘密値が渡ります。ヘッダーと本文をログ上で伏せる `Upstash-Redact-Fields` を設定します。
- 工程は4分でタイムアウト、QStashの接続待ちは5分です。待機中はストリームを維持します。
- QStashの重複排除に加え、D1の実行権とジョブID・工程IDの一致で、再配信が次の工程を誤って実行するのを防ぎます。
- 中断した実行権は10分で期限切れになります。15分ごとの回復スケジュールが待機・期限切れのジョブを拾います。スケジュールはこのアプリ専用の固定IDで作成し、設定の再送でも増殖させません。
- 再配信やサービス障害をまたいだAI呼び出しの厳密な一度限り実行は保証できません。AI側で完了後に保存できなかった場合、再試行の利用料が発生する可能性があります。

## 無料枠の管理

公式料金: https://upstash.com/pricing/qstash

QStash Freeは1日1,000配信、HTTP応答待ち15分まで。リトライも配信数に含まれます。

このアプリは通常のメッセージ登録（接続確認を含む）をUTC日付ごとに300回までに制限します。回復スケジュールは1日96回、リトライは各1回までなので、その日に登録した処理の配信予定数は最大792回です。上限に達した後は即時登録を止め、既存の回復スケジュールで順次進めます。

これはこのアプリの予約回数制限です。他のアプリの利用、日付をまたぐ再配信、QStashの集計時刻によってアカウント全体の利用数は異なります。Upstash側のFreeプランを維持し、管理画面で利用状況を確認してください。DeepSeek API料金は別です。

## 接続確認と解除

- トークンを公式QStashホストのAPIで確認してから暗号化保存します。任意のプロキシURLやリダイレクトへ秘密値を送信しません。
- 保存後、実際のQStash配信で一度限りの確認IDを送り、認証を通ってSitesに到達した場合だけ回復スケジュールを作成し、有効化します。
- 確認メッセージはシナリオを生成せず、DeepSeekを呼びません。
- 「接続確認待ち」のままの場合、QStash Logsの配信結果、トークンとリージョンの組み合わせを確認します。401/403ならSitesの接続情報も確認が必要です。
- 「接続を解除」は当該アプリのスケジュールと保存トークンだけを削除します。他のQStash設定は変更しません。生成中の解除は拒否し、完了後に行います。
- トークン失効時は、待機ジョブが残っていても接続を再設定できます。保存済みの工程は残ります。

## Sites側の環境変数（管理用）

- `AI_CREDENTIAL_SECRET`: 既存の暗号化秘密値。DeepSeekキーを含む保存済みの値がある間は変更禁止。
- `SITES_AUTH_TOKEN`: 本人専用Sitesへ接続する既存のBearerトークン。秘密の環境変数として保存。
- `SCENARIO_RUNNER_SECRET`: 実行API専用のランダムな秘密値。
- `BACKGROUND_GENERATION_ENABLED=true`: 接続機能を利用可能にする。実際の生成はD1上のQStash疎通確認も成功している場合のみ有効。

QStashのユーザートークンは環境変数にはせず、AI設定画面から保存します。

## 検証

`node scripts/check-qstash-worker.mjs` は実WorkerランタイムとD1で、認証、暗号化、疎通確認後の有効化、工程連鎖、重複・同時配信、期限切れ復旧、日次制限、解除を検証します。外部QStashとAIは模擬応答です。

実アカウントとの疎通・画面を閉じた後の実生成は、ユーザーが接続設定を完了した後に確認します。
